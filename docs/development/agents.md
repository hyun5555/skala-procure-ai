# 개인 개발의 Agency Agents 활용

프로젝트 공통 규칙은 루트 `AGENTS.md`다. 이 문서는 설치된 커스텀 역할을 이 프로젝트에서 어떻게 사용할지 정한다.
역할 목록은 실행 설정이 아니며 자동으로 여러 에이전트를 시작하지 않는다. 실행 도구가 지원하는 정확한 이름을 지정한다.
작은 변경은 현재 에이전트 한 명이 완료한다. 전문 검토가 필요할 때 아래 역할을 선택한다.

| 역할 이름 | 맡길 작업 | 소유 범위·완료 기준 |
| --- | --- | --- |
| Software Architect | 변경 경계, 호환성, 단계별 이전 설계 | `docs/architecture/`와 지정 백로그; 단계·대안·검증 기준 |
| AI Engineer | 조건 추출, 출력 검증, 설명, fallback, 평가 | `recommend-service/` 중 지정 파일; 누락·모델 오류에서도 수동 흐름 유지 |
| Backend Architect | 견적·발주·권한·데이터 마이그레이션 | 지정 Java 서비스와 migration; 금액·상태·이벤트·소유권 계약 검증 |
| Frontend Developer | 자연어 입력, 조건 확인, 비교 화면 | `vue-frontend/` 중 지정 파일; 로딩·오류·수동 입력·빌드 검증 |
| Test Automation Engineer | 구매 흐름 회귀와 핵심 E2E | 지정 테스트; 조건 확인부터 발주·성과 반영까지 재현 가능한 검사 |
| Application Security Engineer | API 키, 권한, 입력·문서 신뢰 경계 | 지정 기능의 읽기 전용 검토 우선; 재현 근거와 수정·재검증 결과 |
| DevOps Automator | 재현 가능한 실행과 인증·게이트웨이 교체 | 지정 Docker·CI·배포 파일; 외부 이미지 의존과 환경별 callback 검증 |

현재 단계의 실제 위임은 Software Architect 한 역할로 시작한다. AI Engineer와 Frontend Developer는 첫 기능 계약이 정리된 뒤 필요한 작업에 사용한다.
보안·테스트 역할은 검토 대상 변경이 있을 때 호출한다. 모든 역할을 매번 실행하는 절차는 만들지 않는다.
개발 에이전트와 제품 안의 LLM은 다르다. Agency Agents를 사용한다고 제품에 다중 에이전트 런타임을 추가하지 않는다.

## 작업을 넘길 때

1. 사용자 목표와 이번 작업의 완료 기준
2. 현행 계약과 바꾸려는 동작
3. 직접 소유하는 파일·수정 가능 범위
4. 같은 작업 트리의 다른 작업자와 덮어쓰기 금지
5. 수행할 검증과 환경 제약
6. 결과로 받을 변경 파일·관측 근거·검증·남은 항목

동일 파일을 여러 역할에게 동시에 배정하지 않는다. API 계약→서버 구현→화면 연결처럼 의존하는 작업은 순서대로 수행한다.
실제 결과와 검증을 확인한 뒤 통합한다. 실행 ID나 결과가 없으면 역할 실행으로 보고하지 않는다.

## 요청 예시

“Software Architect 에이전트로 자연어 구매 요청 API 계약을 설계해줘. 수정 범위는 `docs/architecture/`이며 현재 경로 호환성을 유지해줘.”

“AI Engineer 에이전트로 확인된 조건 스키마의 입력 검증과 실패 처리를 구현해줘. 지정 파일만 수정하고 실제 LLM 호출 전에 가짜 응답으로 검증해줘.”

“Frontend Developer 에이전트로 추출된 조건을 수정·확인하는 화면을 만들어줘. `vue-frontend/`만 수정하고 금액과 최종 업체 점수는 서버 응답을 사용해줘.”

“Test Automation Engineer 에이전트로 필수 인증 누락·예산 초과·LLM timeout 구매 흐름을 검증해줘. 새 테스트만 맡고 제품 코드는 수정하지 말아줘.”

## 프로젝트 적용 범위

설치된 Agency Agents는 다른 프로젝트에서도 쓰는 전역 역할이다. 프로젝트 전환으로 전역 TOML·모델·권한을 바꾸지 않는다.
개인 작업 규칙은 `AGENTS.md`와 이 문서로 적용한다. Claude의 진입점은 `CLAUDE.md`이며 같은 원본을 참조한다.
현재 도구에서 특정 역할 실행이 지원되지 않으면 한계를 알리고 현재 에이전트가 수행한 작업으로 구분한다.
