## 검증 기반의 후속 정리

CI는 현재 문서·호환성·프론트 빌드를 검사한다. 다음 코드 변경부터 변경 서비스의 테스트를 CI에 연결하고 프론트 의존성 lock을 정리한다.
이는 Java 변경 금지가 아니다. Vite config의 `__dirname` 경고는 기존 설정의 비차단 경고로 별도 작은 정리 작업에서 처리한다.

## 검증 방법

1. 규칙은 작은 고정 카탈로그 사례로 정상·경계·누락·금액 정밀도를 검증한다. 기존 QCD 산식의 예시는 별도 기준으로 보존한다.
2. API 연결 때 JWT 역할·신원·타인 데이터·게이트웨이 경로를 확인한다. 0개 후보와 외부 서비스 실패가 서로 다른 응답이어야 한다.
3. 화면 변경 시 Vue build와 실제 조건 확인·수정·수동 fallback 흐름을 확인한다. 기존 로그인·품목 조회·발주·결제·품질 등록은 영향받는 단계에서 회귀 확인한다.
4. 스키마 변경은 기존 데이터 사본에서 백필·이벤트 중복·복구 절차를 검증한다. `docker compose down -v`로 검증을 대신하지 않는다.

작업마다 구현 담당 한 명과 필요한 검증 역할만 사용한다. 코드베이스 탐색은 Explorer/Codebase Onboarding Engineer, 설계는 Software Architect, 기능은 AI Engineer·Frontend Developer, 권한은 Application Security Engineer가 맡는다. 작은 문서·라벨 수정은 별도 에이전트나 테스트 구조를 만들지 않는다.
