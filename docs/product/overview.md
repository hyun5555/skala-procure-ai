# 제품 개요

**AI 기반 품질 데이터 활용 산업용 자재·가공업체 매칭 및 조달 플랫폼** — B2B2B

출처는 팀 기획안 `AI_품질데이터_산업조달플랫폼_기획안.pdf` 이며, 이 문서는 개발 중에 참조할 요약이다. **기획안과 이 문서가 다르면 기획안이 맞다.** 다르다는 것을 발견하면 이 문서를 갱신하고, 어느 쪽이 의도인지 불확실하면 임의로 정하지 않고 묻는다.

## 한 문장

구매 제조기업이 필요한 품명·규격·수량·예산·공급지역·납기 조건을 입력하면 조달 등록 데이터의 가격, 납품일수, 인증, 우수제품·MAS 여부와 향후 누적되는 품질지표를 종합해 적합한 업체를 추천하고, 견적·발주·결제·납품·품질검사까지 연결하는 조달 플랫폼이다.

단순 업체 검색이 아니라 **거래 이후 발생한 품질 데이터를 다시 공급업체 평가와 추천에 활용하는 피드백 구조**가 핵심 차별점이다.

## 이해관계자와 Pain Point

| 이해관계자 | 저장소에서의 역할 | Pain Point |
| --- | --- | --- |
| 구매 제조기업 | `STUDENT` | 여러 업체의 가격·납기·품질정보를 개별 확인해야 한다. 가격, 가공능력, 납기, 과거 불량률이 서로 다른 문서에 흩어져 있어 비교에 시간이 오래 걸리고 의사결정의 일관성도 떨어진다 |
| 소재·가공 공급기업 | `INSTRUCTOR` | 기술력이 있어도 신규 거래처 확보가 어렵다. 품질 성과를 증명할 공통 지표가 없다 |
| 플랫폼 운영자 | **로그인 역할로 만들지 않는다** | 단순 중개만으로는 차별화가 어렵다 |

운영자를 로그인 역할로 만들 수 없는 이유는 auth-server가 역할 2종을 고정하기 때문이다. [`../constraints.md`](../constraints.md)의 `사용자 역할은 2종뿐이다` 를 본다.

**왜 이 문제가 중요한가.** 가격이 저렴해도 불량률이 높으면 재검사, 선별, 재작업, 교체, 재발주, 생산 일정 변경 등의 추가 비용이 발생한다. 구매 담당자가 찾아야 하는 것은 가장 싼 업체가 아니라 **우리 요구조건에서 실제로 가장 안정적으로 납품할 업체**다.

## AI의 역할

AI가 들어갈 자리는 **recommend-service 한 곳**이다. 나머지 서비스는 CRUD와 결제·이벤트 배선이다.

AI가 하는 일은 하나로 요약된다 — **서로 다른 축의 지표를 하나의 판단으로 합치고, 그 근거를 사람이 읽을 수 있게 설명하는 것.**

핵심 기능은 셋이다.

1. **조건 기반 공급업체 추천** — 품명·세부품명·규격·수량·예산·공급지역·납기를 입력하면 필수조건으로 1차 필터링하고, 가격·납품일수·인증·우수제품·MAS 정보를 점수화해 순위를 만든다
2. **추천 근거 제시** — 점수만 보여주지 않고 "30일 납품, 예산 충족, KS 인증, MAS 등록"처럼 판단 재료를 함께 표시한다
3. **품질 데이터 재활용** — 납품 후 등록한 불량률이 공급업체 품질지표를 갱신하고, 다음 추천에 반영된다

**추천은 AI가 결정하는 방식이 아니라 구매 담당자가 판단할 수 있도록 비교 근거를 제공하는 의사결정 지원 도구로 설계한다.**

초기 구현은 복잡한 머신러닝이 아니라 **조건 필터링 + 규칙 기반 점수화**로 한다. 공급업체 선정 자체가 다기준 의사결정 문제이므로 방향이 맞다. 거래 데이터가 쌓인 뒤 머신러닝 기반 불량 위험·납기 지연 예측으로 확장하는 로드맵을 제시한다.

### 점수 배점

MVP 예시이며 산업 표준이 아니다. 실제 서비스에서는 구매기업마다 가중치를 다르게 설정할 수 있다.

| 평가 요소 | 배점 | 평가 방식 |
| --- | --- | --- |
| 품목 적합 | 30 | 품명·세부품명·규격 키워드 충족 여부 |
| 가격 | 25 | 수량과 총예산 대비 등록 단가 |
| 납기 | 20 | 최대 납품일수 충족 여부 |
| 공급지역 | 10 | 요청 지역 공급 가능 여부 |
| 인증 | 10 | KS 등 요청 인증 보유 여부 |
| 조달 등록 | 5 | 우수제품·MAS 등록 여부 |

## 도메인 매핑

원본 템플릿의 개념을 이렇게 치환한다. **경로와 enum 값은 바꾸지 않고 의미만 바꾼다.**

| 템플릿 개념 | 조달 플랫폼 | 저장소 위치 |
| --- | --- | --- |
| 강사 | 공급기업 | `users.role = INSTRUCTOR` |
| 수강생 | 구매기업 | `users.role = STUDENT` |
| 강의 | 소재·가공 서비스 | `courses` |
| 강의 카테고리 | 조달 품명군 | `courses.category` (8칸 enum 슬롯) |
| 수강료 | 기준 단가 | `courses.price` |
| 수강생 수 | 누적 거래건수 | `courses.enrollment_count` |
| 수강신청 | 견적·발주 요청 | `enrollments` |
| 결제 대기 | 발주 접수 | `enrollments.status = PENDING` |
| 수강 중 | 주문 확정 | `enrollments.status = ACTIVE` |
| 결제 | 주문 결제 | `payments` |
| 추천 강의 | 추천 공급업체 | recommend-service |

| MSA 서비스 | 프로젝트에서의 역할 |
| --- | --- |
| user-service | 구매기업·공급기업 회원 및 권한 |
| course-service | 소재·가공 서비스 (Product) |
| enrollment-service | 견적·발주·주문 (Order) + 품질검사(Sprint2) |
| payment-service | 주문 결제 |
| recommend-service | 공급업체 매칭·추천 |

**품질 기능을 별도 MSA로 만들지 않는다.** 게이트웨이에 새 경로를 만들 수 없고, 난이도도 올라간다. enrollment-service에 붙인다.

## 서비스 흐름

```text
공급기업 가입 → 조달 품목·납품조건 등록
   ↓
구매기업이 품명·규격·지역·예산·납기 입력 → 1차 필터링 → 점수화 추천
   ↓
추천 근거 확인 → 발주 → 결제 → 주문 확정
   ↓
납품 → 품질검사 등록 → 불량률 계산 → 공급업체 품질지표 갱신
   ↓
갱신된 데이터가 다음 추천에 반영
```

## Sprint 구분

가이드의 워킹 스켈레톤 정의를 따른다. **여러 서비스를 조금씩 건드리는 것이 아니라 한 흐름을 처음부터 끝까지 완전히 만든다.**

### Sprint 1 — 기본 조달 MVP

목표: 새 도메인 언어로 된 화면에서 **등록 → 조회 → 발주 → 결제 → 확정이 끊김 없이 이어진다.**

- 기업 회원가입·로그인
- 공급기업 가공 서비스 등록
- 구매기업 서비스 조회·상세
- 발주 상세정보 저장, 발주 요청, 내 주문 조회
- 기본 추천 또는 필터링

도메인 치환은 프론트엔드 라벨 맵 교체로 처리하되, 구매자가 입력한 발주 상세정보를 서버에 보존하기 위해 enrollment-service와 init-db만 확장한다. `payment-service`, Kafka, `recommend-service` 는 원본 그대로 통과시킨다.

완료 기준에 하나를 더한다 — **영문 enum이 화면에 한 글자도 노출되지 않는다.** 원본 상태에서 이미 어긋나 있으므로 8칸을 채우는 것이 Sprint1의 실제 작업이다.

### Sprint 2 — 품질·추천 확장

- Kafka 흐름 시연 (이미 동작하므로 코드 변경 없음)
- 품질검사 등록 — `PATCH /api/enrollments/{id}/quality` 신규
- 불량률 자동 계산, 공급업체 품질지표 갱신
- 추천 응답에 `score` · `reason` · `scoreBreakdown` 추가
- 품질 데이터를 추천 점수에 반영

가벼운 것부터 한다. recommend-service는 파이썬이라 손이 가장 가볍고, payment-service 확장이 가장 무겁다.

## 상용화 시 보정할 점

발표의 `기대 효과` 절에 쓸 재료다. **불량률 하나만으로 공급업체를 평가하면 왜곡된다.**

- 동일하거나 유사한 제품군·소재·가공공정끼리 비교해야 한다
- 고정밀 부품과 단순 부품은 검사 난이도와 품질기준이 다르다
- 신규 공급기업은 거래이력이 없으므로 가공능력·가격·납기·인증 등 기본점수로 초기 평가하고, 거래가 쌓이면 실제 성과 비중을 높인다
- 구매기업마다 품질·가격·납기의 중요도가 다르므로 가중치를 사용자별로 조절할 수 있게 확장한다
- 불량률은 미래 성과의 확정값이 아니라 **과거 성과를 기반으로 한 의사결정 참고지표**로 표시한다

## 미결정

임의로 확정하지 않는다. 결정되면 이 절에서 지우고 위 본문에 반영한다.

- 결제 금액을 카탈로그 단가로 계산할 것인지, 시연 단가를 고정값에 맞출 것인지 → [`../constraints.md`](../constraints.md)의 `결제 금액이 고정되어 있다`
- CSV의 9개 품명 중 희소 품목(`커플링식관이음`·`융복합관류`)은 `기타 관류` 슬롯으로 묶는다
- `description` 에 스펙 정보를 담을 때 쓸 구분자
